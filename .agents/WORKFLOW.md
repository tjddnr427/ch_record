# 생성 · 검토 · 리뷰 워크플로우

## 구조
- generator/ROLE.md: 구현
- validator/ROLE.md: 실행 검증
- reviewer/ROLE.md: 독립 결함 리뷰
- templates/task.md: 작업 명세와 인계 양식
- runs/<작업ID>/: task.md, validation.md, review.md

이 폴더는 프로젝트 작업 규약이다. 폴더 생성만으로 런타임에 사용자 정의 에이전트가 등록되거나 자동 실행되지는 않는다. 주 에이전트가 제공된 위임 도구로 역할 지침을 전달한다. 모델·권한·전역 설정을 임의 변경하지 않는다.

## 실행 순서
1. 주 에이전트가 PRD와 기존 상태를 확인하고 작업 ID, 범위, FR/NFR, T ID, 담당 파일, 수용 조건을 task.md에 작성한다.
2. 생성 에이전트가 구현·필요한 테스트를 작성하고 변경 파일, 결정, 실행 결과, 미해결 항목을 인계한다.
3. 검토 에이전트가 실제 파일을 확인하고 검증을 실행한다. validation.md에 PASS / FAIL / BLOCKED / NOT_RUN과 근거를 남긴다.
4. 리뷰 에이전트가 PRD, 실제 구현, 검증 기록을 독립적으로 확인하고 review.md에 결함과 판정을 남긴다.
5. 생성 에이전트가 결함을 수정하고 영향받은 검토·리뷰를 반복한다. 같은 장애가 반복되면 원인과 필요한 입력을 명시한다.
6. 주 에이전트가 결과를 통합하고 완료 또는 환경 검증 보류를 보고한다.

## 완료 기준
- 수용 조건을 실제 증거로 충족한다.
- 데이터 손실·개인정보 노출·충돌·핵심 기능 오동작 결함을 해결한다.
- 그 외 결함은 영향과 후속 작업을 기록한다.
- 필수 환경 검증이 보류되면 해당 Phase 전체 통과를 선언하지 않는다.
- 수정 후 이전 증거의 유효성을 확인한다.
