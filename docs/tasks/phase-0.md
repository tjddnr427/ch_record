# Phase 0 생성 준비

상태: IMPLEMENTED / HARDWARE_BLOCKED. PoC 생성 및 mock 검증 29개 통과. 실장치 검증은 의존성·환경 미확보로 보류. 결과: docs/phase-0-results.md.
입력: PRD.md 7~12·16~17절, AGENTS.md, docs/ENGINEERING.md.
목표: 실제 GPU 추론 및 2트랙 캡처 가능성을 확인하고 그 결과에 따라 최소 제품 구조와 버전을 결정한다.

## 메인 AI 선행 작업
- Python 3.11 x64, FFmpeg/ffprobe, NVIDIA 장치·드라이버, 설치 패키지, 출력·마이크 장치를 조사한다.
- 패키지 변경 전 의존성 설치를 조율한다. 검증 전 버전을 호환 확정으로 잠그지 않는다.
- 아래 파일 경계와 결과 형식을 확정하고 사용 가능한 하위 모델을 선택한다.

## 병렬 생성 단위
1. GPU PoC: 담당 tools/poc_stt.py 및 관련 테스트. 10초 로컬 샘플, 한국어, large-v3, beam 5, 실제 GPU 처리 시간과 실패 원인을 확인한다. 연결 FR-07~09, T01/T11. 원문·개인 경로를 기본 로그에 출력하지 않는다.
2. 캡처 PoC: 담당 tools/poc_capture.py 및 관련 테스트. 30초 loopback+마이크를 별도 트랙으로 디스크 기록하고 단조 시간·프레임 수를 보존한다. 연결 FR-02~06, T04/T05. 무신호를 성공 처리하지 않는다.

공유 의존성 설정과 결과 명세는 메인 AI가 소유한다. 두 생성 작업의 파일 소유권을 분리한다. 디렉터리와 모듈은 해당 구현을 시작할 때 생성한다.

## 의존 작업
캡처 PoC 결과를 받은 후 1분 동기화 검증을 수행한다. 시작 시각, 프레임 수, 샘플레이트, 트랙 길이를 비교하고 차이를 수치로 기록한다. 허용 오차는 검증 전에 명시하고 근거를 남긴다. 1분 결과로 장시간 drift 테스트 T08을 통과 처리하지 않는다.

## 수용 조건
- 실제 실행 명령, 환경, 패키지 버전, 성공·실패·보류 근거가 남는다.
- 10초 GPU 변환, 30초 2트랙 캡처, 1분 동기화 각각을 독립적으로 판정한다.
- 누락된 GPU·DLL·모델·장치·샘플은 구체적 보류 사유로 기록한다.
- 환경과 mock을 구분하고 실제 검증 전 lockfile을 호환 확정으로 표현하지 않는다.
- 검토 에이전트가 실행 결과를 확인하고 리뷰 에이전트가 실제 코드와 설계 기준을 확인한다.
- 메인 AI가 결과를 통합하고 Phase 1 진입 가능 여부를 판단한다.

비목표: 전체 GUI, 범용 엔진 프레임워크, 플러그인 체계, 배포 패키지 선행 구현.
